## 1. Логи

```bash
# всё, включая слова (уровень debug)
log stream --level debug --predicate 'subsystem == "com.switchfix"'
# только решения и коррекции, без debug
log stream --level info --predicate 'subsystem == "com.switchfix"'
# одна категория
log stream --level debug --predicate 'subsystem == "com.switchfix" AND category == "lexicon"'
# задним числом, за последние 10 минут
log show --last 10m --level debug --predicate 'subsystem == "com.switchfix"'
```

⚠️ **Приватность.** Строки уровня `debug` и строка `detect '…' -> '…'` (уровень notice, категория
detector) содержат набранные слова. Пароли в защищённых полях не перехватываются, но в обычных
полях — да. Не вставляй сырые логи в issue или чат без просмотра. Для отчётов бери строки
`model decision` и `lexicon …` — в них слов нет.

Что искать (все строки начинаются с `[SwitchFix]`):

| Категория | Строка | Смысл |
|---|---|---|
| app | `automatic correction unavailable for layouts: …` | модель раскладки не загрузилась — автокоррекции для неё нет (**баг сборки**) |
| detector (info) | `model decision corrected=true margin=… threshold=… letters=…` | модель решила исправить; слова нет — **главный материал для калибровки** |
| detector (info) | `model decision corrected=false margin=… letters=…` | модель решила оставить |
| detector (debug) | `model: 'ghbdtn' → 'привет' margin=… threshold=…` | то же со словом |
| detector (debug) | `model: '…' → common short word '…'` | короткое слово по таблице `ShortWordTable` |
| detector (debug) | `lexicon: keep (length N)` / `lexicon: convert to russian (length N)` | сработало правило из «Слов» |
| detector (notice) | `detect '…' -> '…' source=… target=… switch=…` | итог детекции |
| engine | `force: source=… alternatives=…` | принудительная конвертация хоткеем |
| engine | `correction cancelled reason=…` | коррекция отменена защитой от устаревшего контекста (это норма, если в момент коррекции вы продолжали печатать) |
| correction | `correction APPLIED '<private>' …` / `revert APPLIED …` | текст реально заменён / откат (здесь `os.Logger` без public, слова скрыты как `<private>`) |
| lexicon | `lexicon saved entries=N` | лексикон записан (через ~2 с после изменения правил) |
| lexicon | `lexicon unreadable …` / `… unreadable entries skipped …` | повреждённые данные, оригинал сохранён под ключом `SwitchFix_personalLexicon.unreadable` |

## 2. Состояние на диске

```bash
defaults read com.switchfix.app SwitchFix_detectionSensitivity      # 0…4, нет ключа = 2 (по умолчанию)
# выученные слова (JSON внутри plist)
defaults export com.switchfix.app - | python3 -c '
import plistlib, sys, json
p = plistlib.loads(sys.stdin.buffer.read())
for e in json.loads(p.get("SwitchFix_personalLexicon", b"[]")):
    print(e["word"], e["sourceLayout"], e["rule"], e["origin"], e.get("matchCount"), e.get("lastMatchedAt"))'
```

- Счётчики срабатываний (`matchCount`) пишутся на диск лениво: при следующем изменении правил или при
  выходе из приложения. Вкладка «Слова» показывает актуальные значения из памяти.
- Начать с чистого лексикона: выйди из SwitchFix, затем
  `defaults delete com.switchfix.app SwitchFix_personalLexicon`, затем запусти снова.

Горячие клавиши по умолчанию: **Исправить** — Ctrl+Shift+Space, **Отменить последнее** — Caps Lock.
Их можно переназначить во вкладке «Исправление».

## 3. Сценарии

Каждый пункт — ожидаемое поведение. При расхождении: сохрани строки лога (§1) за момент ошибки, точный
набранный текст, приложение, раскладку и положение ползунка, затем зафиксируй это (§4). Режим
исправления — «Автоматически», если не сказано иначе.

### A. Детекция (основной сценарий)
1. В родной раскладке набери «создай новую цщклекуу » (раскладку не переключать) → `worktree`,
   раскладка переключается на английскую.
2. На английской раскладке набери «ghbdtn » → `привет`; «hf,jnftn » → `работает` (словоформы
   исправляются — словарь этого не умел).
3. Правильно набранные слова не трогаются: «hello », «deadline », «было », «пятницу », «дякую ».
4. Идентификаторы и URL не трогаются: `getValue`, `https://example.com`, `user@mail.com`, `12345`,
   `API`.
5. Русский ↔ украинский автоматически не конвертируется никогда (обе кириллические раскладки
   установлены: «было» остаётся «было»).
6. Если установлены обе кириллические раскладки: латиница уходит в ту, которой пользовались последней.

### B. Обучение на отмене
1. Набери «ghbdtn » → исправилось на «привет».
2. Сразу нажми **Отменить последнее** → вернулось `ghbdtn`, в логе `revert APPLIED`, через ~2 с
   `lexicon saved entries=…`.
3. Вкладка «Слова»: запись `ghbdtn · EN · Не исправлять · Отмена`.
4. Снова набери «ghbdtn » → не исправляется; в логе `lexicon: keep (length 6)`.
5. Удали запись во вкладке → снова исправляется.

### C. Обучение на хоткее
1. На английской раскладке набери «rehk» (модель его не узнаёт) и нажми **Исправить** → `курл`; в логе
   `force: …`.
2. Вкладка «Слова»: `rehk · EN · Исправлять → RU · Хоткей`.
3. Набери «rehk » с пробелом → исправляется автоматически, раскладка переключается сразу.
4. Хоткей на слове из 1–2 символов (например «b») переводит, но **не** запоминается.
5. Хоткей, а сразу после него **Отменить последнее** → урок забыт (записи нет).
6. **Отменить последнее**, когда отменять нечего (например, после нового набора), конвертирует слово,
   но **ничего не запоминает**.

### D. Не должно учиться
1. Выделение текста + хоткей (замена выделения) → записи не появляется.
2. Режим «При смене раскладки» → записи не появляется.
3. Поле пароля (например, в Связке ключей или на странице входа в Safari) → не корректируется и не
   учится.
4. Приложение, исключённое во вкладке «Приложения» → ничего не происходит.
5. Два слова, склеенные коррекцией (короткое слово, отложенное до следующего: «ше цщкли» →
   «it works»), при отмене не учатся.

### E. Вкладка «Слова»
- **+**: добавление; проверь ошибки формы:
  - пустое слово;
  - больше 64 символов;
  - «привет» в раскладке English → «эти символы нельзя набрать…»;
  - русский → «Исправлять в» украинскую недоступна: в списке целей для кириллицы только English;
  - дубликат → «Это слово уже есть в списке…».
- Двойной клик и кнопка «Изменить…» открывают правку; в форме видны срабатывания и последнее
  срабатывание.
- Правка выученной записи превращает её во «Вручную». После этого отмена и хоткей её больше не меняют.
- Удаление:
  - кнопкой **−**;
  - клавишей Delete;
  - пунктом «Удалить» в контекстном меню;
  - при множественном выделении.

  Если поиск скрыл часть выделенных строк, удаляются только видимые.
- Поиск, фильтр «Все / Не исправлять / Исправлять», сортировка по каждой колонке.
- Подсказка при наведении на ячейку: «Последнее срабатывание: …» или «Ещё не срабатывало».
- Меню «…»: «Сбросить выученные…» (ручные записи остаются) и «Удалить все слова…» — оба с
  подтверждением.
- Язык интерфейса «Русский» (вкладка «Основные»): все строки вкладки переведены, ничего не падает.
- Вкладка помещается в окно (ширина 520 pt), колонки не обрезаны до нечитаемости.

### F. Ползунок «Чувствительность»
- 5 положений; подпись под ползунком меняется. Если режим не «Автоматически», ползунок неактивен.
- Изменение действует сразу, без перезапуска: `defaults read … SwitchFix_detectionSensitivity`
  меняется, а в `model decision … threshold=…` порог сдвигается на ±2 за деление.
  - Для слов из 7+ букв: 9 → 7 → 5 → 3 → 1, от «Осторожно» до «Смело».
  - Для 4–6 букв: 12 → 10 → 8 → 6 → 4.
- «Смело» исправляет больше пограничных 4–5-буквенных слов, «Осторожно» — меньше. Короткие слова
  ползунок не затрагивает.

### G. Регрессия старого поведения
- Хоткей на выделении, повторная конвертация туда и обратно (`ghbdtn, vbh` ⇄ `привет, мир`).
- Telegram и Electron-приложения (Claude, Chrome) с их режимом ввода из вкладки «Приложения».
- Переключение раскладки клавишей 🌐 не теряет нажатия.
- После перезапуска приложения лексикон и положение ползунка сохраняются.

- Всё прошло:
  `rtp verify 2026-09-29-ngram-only-learning-ui --record "Проверено на macOS <версия>, сценарии A–G" --out "<кратко что видели>"`.
  Затем закрой пункт долга «Проверить вкладку «Слова» и ползунок…» через `rtp debt … --close` и
  переведи задачу: `rtp phase … --to done --log "…"`.
- Найден баг — **новая задача** через `run-task-pipeline` (`rtp new`, для багов — скилл
  `systematic-debugging`). В описании:
  - сценарий из §3;
  - что набрано, где, какая раскладка, положение ползунка;
  - ожидание и факт;
  - строки лога без паролей и личного текста (предпочтительно `model decision …`).

  Неверное решение модели (слово не исправилось или исправилось лишнее) — не баг кода, а данные
  калибровки. Собери `margin`, `threshold` и `letters` из `model decision` и добавь в долг задачи (там
  уже есть пункт про базовые пороги).
- Стоит проверить в логах, как часто `corrected=false` получает `margin` чуть ниже `threshold` на
  словах, которые пользователь потом исправляет хоткеем. Это прямой аргумент за сдвиг значения по
  умолчанию (см. `thresholds_005.md`).
- Изменения кода — только на ветке задачи, через пайплайн. CI (`.github/workflows/ci.yml`) должен
  остаться зелёным. Локально перед пушем:
  - `swift build -c release`;
  - `swift run -c release TestRunner` (из корня репо);
  - `swift run -c release InputPipelineTestRunner`.
