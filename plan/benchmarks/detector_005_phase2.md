# Фаза 2: n-граммный детектор против словарного (plan 005)

> **Дата**: 2026-09-29
> **Коммит**: `592ea8c` (CI run 45, macos-15). Оба движка прогоняются на одних данных:
> `swift run -c release TestRunner --layout-eval-only`.
> **Движок `ngram`**: модели `*.sfng` (Фаза 1), `ShortWordTable` (150 самых частых слов
> 1–3 буквы на язык из корпусов обучения), пороги T3=12, T4=T5=T6=8, T7+=5, автоконвертация
> только английский ↔ родная раскладка.
> **Включить в приложении**: `defaults write com.switchfix.app SwitchFix_detectionEngine ngram`
> и перезапуск (по умолчанию пока `dictionary`).

Оставшиеся провалы:
- `тесты упали на [СШ]` — `CI` на кириллице: аббревиатура из 2 букв подавляется
  сильным контекстом родного языка (так же ведёт себя словарный движок).
- `опиши [игп]` (`bug`), `у мене [дфп]` (`lag`), `немає [штвуч]` (`index`) — короткие
  английские слова, у которых отступ ниже порога.
- `для [ws']]` / `у [g'znybw.→пєятницю]` — украинские `ї/є/'` на клавишах пунктуации:
  `LayoutMapper` не знает, где на macOS-раскладке апостроф, поэтому часть таких слов
  в тестах недостижима. Отдельная задача для маппера, не для модели.

## 5. Второстепенная конфигурация: все три раскладки

Без истории переключений (в изолированном тесте детектор ни разу не видел кириллицу)
латиница конвертируется в ту кириллическую раскладку, чья модель даёт больший отступ, и
украинский часто уходит в русский: uk в раскладке en — 73.65% (1157 в неверный язык),
ru — 82.84%. В реальной работе цель — последняя активная кириллическая раскладка
(`lastCyrillicLayout`), поэтому это худший случай. Порчи русского текста украинским
(`было→біло`, 2.34% у словаря) больше нет: ложные для ru — 0.26%, как в основной
конфигурации.
